00RESEARCH DOSSIER

The question, the artifacts, and the next evidence—without repository archaeology.

The current research question is whether an evidence-governed modular reasoning workflow can improve traceability, verification discipline, and independent usefulness of AI-assisted research without confusing agreement, confidence, or passing software checks with scientific validity. The repository implements the architecture and mechanical/specification checks; a positive answer to the full behavioral question has not been established.

02ADAPTIVE REASONING COMPLEMENT

A weak result is a clue.
Not a permanent label.

FOIL maintains competing explanations for observed performance, conditions evidence on assistance and context, supplies the smallest useful complement, and separates immediate joint success from later independent competence.

04EXPLORATORY PILOTS

Publish the null result beside the positive result.

These are small deterministic disjoint-subset pilots using GPT-5.6 Sol, not official leaderboard submissions or isolated same-item causal A/B tests. Earlier closed-book pilots use a frozen Frontier-Exam FOIL + Mastermind condition; the BrowseComp pilot separately ablates generic FOIL, a frozen benchmark-blind profile, and a Mastermind final audit.

HLE / PUBLIC TEXT SUBSET+16.7 pp

BASE 1/6 → assisted 2/6. Blinded CI-scored pilot; 16.7% to 33.3%.

ARC-AGI-1+16.7 pp

BASE 4/6 → assisted 5/6. Blinded CI-scored pilot; 66.7% to 83.3%.

GPQA-DIAMOND0.0 pp

BASE 9/12 → assisted 9/12. The larger follow-up produced a null result.

BROWSECOMP / FOUR-WAY1/2 · 2/2 · 1/2 · 0/2

BASE · FOIL · PROFILE · MASTERMIND. Two disjoint items per condition; exact-normalized scoring, no significance claim.

Validity boundary

Disjoint subsets, small n, documented contamination/execution exclusions, and exact-normalized scoring where specified. Pilot benchmark results do not establish general efficacy.

05REPRODUCIBILITY

A reviewer should be able to rerun the mechanical claims.

The public reproducibility contract distinguishes repository/specification properties from behavioral research. A validation pass establishes only the invariants that the validator actually checks.

MECHANICAL VALIDATION / CLEAN CHECKOUT 
python validation/validate_soul_gauntlet_public.py
python validation/validate_showcase.py
python -m compileall -q validation
WHAT A PASS MEANS
  • Checked repository, package, and showcase invariants passed.
  • Referenced source artifacts are present and internally consistent.
  • Browser layout checks pass in the documented validator environment.
WHAT IT DOES NOT MEAN
  • It does not prove model behavior, research efficacy, or downstream scientific validity.
  • PASS-SPEC does not mean the complete executing system has been behaviorally validated.
