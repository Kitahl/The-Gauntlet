ONE CONTROL SURFACE · MANY SPECIALIST TOOLS

The Gauntlet

Powerful tools already exist. The hard part is choosing and combining the right ones without losing track of what they actually proved.

The Gauntlet makes that easier. Give it the goal; it frames the task, routes each load-bearing obligation to the right specialist method, records what was actually checked, audits the process, and releases only the conclusion the evidence supports. Mirror adapts that routing by identifying the smallest task-relevant complement that is missing.

00HOW IT WORKS

A research task moves through five explicit stages.

The point is not to make more agents talk. The point is to turn one goal into explicit obligations, select the right specialist tools, preserve evidence provenance, and keep unresolved claims unresolved.

  2. 02Obligatewhat must actually be established?

  4. 04Receiptinput · output · provenance · limits

01THE FIVE GEMS

Click a Gem to see what it does.

Each Gem is a bounded specialist route with a different evidentiary job. They are not five personalities voting on the same answer.

◆MindFormal Reasoning · /mindOpen

Turns mathematical and logical claims into explicit objects, assumptions, negations, and proof obligations.

formalize→choose verifier→counterexample search→scoped verdict
Use when
Proof, logic, probability/statistics, causal formalization, optimization, complexity, or exact countermodels are load-bearing.
Power
Exact derivation, solver/proof-checker execution, enumeration, numerical computation, theorem/source entailment.
Evidence states
PROVEN, MEASURED, CITED, DERIVED, otherwise unresolved.
Read the Mind specification ↗
◆SpaceResearch Discovery · /spaceOpen

Searches before novelty: papers, repositories, standards, current facts, implementations, and cross-domain prior art.

translate mechanism→search primary sources→expand & dedupe→scope the finding
Use when
“Has this been done?”, literature review, prior art, current external facts, source verification, or reusable code/tool discovery.
Power
Multi-index discovery, citation/source inspection, license/version/guarantee checks, transport-limit analysis.
Boundary
NOT FOUND means not found within the stated search scope; it never proves nonexistence.
Read the Space specification ↗
◆RealityMethod Synthesis · /realityOpen

Invents only after Space establishes the nearest known approaches and a named constraint they fail.

named gap→constraint table→candidate mechanisms→recheck & falsify
Use when
A verified prior-art boundary leaves a concrete unresolved mechanism gap.
Power
Changes assumptions or representations, records inputs/outputs/invariants/dependencies/failures, and proposes verification plans.
Admission
Causal adequacy, negative control, transfer, ablation, regression, and renewed prior-art checking.
Read the Reality specification ↗
◆PowerEngineering Verification · /powerOpen

Converts executable software claims into runnable checks and preservation obligations.

inspect artifact→smallest complete change→execute→regressions & receipt
Use when
Implementation, debugging, integration, architecture, software correctness, runtime behavior, or code review is load-bearing.
Power
Targeted tests, real-entrypoint execution, static/dynamic checks, failure-class coverage, hashes and verifier receipts.
Boundary
A green unit suite certifies only those tests; relevant unobserved failure classes must still be named.
Read the Power specification ↗
◆TimeEvaluation & Benchmarking · /timeOpen

Tests whether a mechanism improves the construct that actually matters under an evaluation design that can distinguish the cause.

construct→strong baseline→matched ablation→uncertainty & stop/go
Use when
Benchmarking, baselines, capability claims, ceilings, cost, ablations, matched-budget comparisons, or stop/go decisions.
Power
Frozen endpoints, strong controls, matched resource budgets, paired inference, exclusions, raw failure preservation.
Boundary
Benchmark score is not general capability; more compute is not routing gain; negative results are retained.

Research Orchestrator

Frame → decompose → route → integrate → assure → release.

02 / ADAPTIVE

Mirror

Find the smallest task-relevant missing complement and supply only what is needed.

/foil · legacy ID

Mirror compares current task requirements against current user/context evidence, keeps competing gap hypotheses, and routes the smallest useful complement through existing Gems and tools. It separates tool-assisted task success from later independent transfer. FOIL remains the legacy technical name in code, paths, receipts, and historical benchmark conditions.

04 / PREFLIGHT

Decision Preflight Protocol

Ground the current state before consequential action or after drift.

orchestrator-invoked

STILL → GROUND → ORIENT → WEIGH → RELEASE. It is a short reset, not ceremony: confirm authoritative state, goal, supported facts, assumptions, unknowns and irreversible costs, then choose one high-value next action.

05 / REVIEW

Evidence Review Panel

Selective independent review with commit-reveal and a strong direct control.

/council

Off by default. When justified, 3–6 artifact-derived seats independently commit before cross-critique, include a skeptic, preserve disagreement, and are compared against a matched direct analysis. Agreement is never treated as proof.

05EVIDENCE LEDGER

Four evidence classes. Never blended into one score.

A green engineering gate is not converted into a behavioral research claim. Structural checks, specification coverage, exploratory pilots, and prospective efficacy remain separate.

SPECIFICATION18 / 18

Behavioral-contract coverage

PASS-SPEC means the required decision behavior is represented in specification; it is not execution evidence.

EXPLORATORYMIXED

Selected benchmark pilots

Small, scoped model-task pilots include positive, null, and mixed outcomes.

PROSPECTIVEOPEN

Complete-system efficacy

Matched-budget and independent-transfer evidence remains on the research roadmap.

Interpretation rule

Passing software/specification gates establishes only the properties those gates observe. It does not prove model behavior, research efficacy, or downstream scientific validity.

07REPRODUCIBILITY

A reviewer should be able to rerun the mechanical claims.

The reproducibility contract distinguishes repository/specification properties from behavioral research. A validation pass establishes only the invariants the validator actually checks.

MECHANICAL VALIDATION / CLEAN CHECKOUT
python validation/validate_soul_gauntlet_public.py
python validation/validate_showcase.py
python -m compileall -q validation
WHAT A PASS MEANS
  • Checked repository, package, and showcase invariants passed.
  • Referenced source artifacts are present and internally consistent.
  • Browser layout checks pass in the documented validator environment.
WHAT IT DOES NOT MEAN
  • It does not prove model behavior, research efficacy, or downstream scientific validity.
  • PASS-SPEC does not mean the complete executing system has been behaviorally validated.
